# 数据库设计

Issue #8 新增 `core_modelcall` 与 `core_aievent`。模型调用在任务、执行代次与调用序号内唯一，数据库约束每代次调用序号为 1–4；记录模型、提示词版本、输入摘要、用量（可未知）、耗时和诊断状态。事件只保存安全的类型与计数，不保存模型原始响应或密钥。两者直接隶属于 Job，项目范围由 Job 派生。待核对候选结果保存在成功任务的不可变输出快照中，引用创建时冻结的片段和题录版本，不写入作者 EvidenceNote。

以下为首版逻辑模型。字段、索引和迁移随对应功能提交，不表示数据库已经建立。

Issue #2 已提供 Django 用户/Session，以及 `core_project`、`core_projectmember`、`core_projectpolicy` 的迁移。项目创建者由不可从 API 修改的 `owner_id` 保存，协作者在成员表中按项目与用户唯一；角色限制为作者和审阅者。规则按项目与版本唯一，未核对规则不得包含允许的 AI 功能，已核对规则必须有来源及来源版本。项目与初始规则在同一事务创建，后续规则仅新增；当前规则取该项目最大版本，避免跨项目的当前规则指针。Issue #3 新增 `core_job` 与 `core_jobattempt`：请求键在项目与创建者内唯一，执行代次在任务内唯一，状态与进度范围有数据库约束；租约与当前代次共同阻止旧 Worker 发布。Issue #4 新增微信身份、一次性绑定与小程序会话：身份按 AppID/OpenID 唯一，内部用户在同 AppID 仅绑定一个身份；绑定码和会话 token 只存摘要，解绑撤销已有会话。Issue #5 新增材料与不可变文件版本；上传登记就是待完成的版本记录，文件元数据和对象键直接隶属于该版本，避免跨项目文件外键。版本号在材料内唯一，请求键在创建者内唯一；同一请求不能跨项目复用。Issue #6 新增 `core_parserun` 与 `core_sourcechunk`：解析号在文件版本内唯一，片段序号在解析内唯一；解析只引用文件版本和任务，项目从原件派生。数据库触发器校验解析、任务与原件属于同一项目，并阻止相关父记录移动造成跨项目关联。片段、解析发布时间及任务成功状态在同一事务写入；不同解析历史不覆盖原片段。Issue #7 新增题录及不可变题录修订、证据卡及作者笔记修订、本地嵌入索引及片段向量。证据绑定原片段与捕获时的题录版本，数据库约束两者属于同一文件版本；向量维度须与索引一致，原片段与索引任务须属于同一项目。材料状态版本随撤回/恢复递增，旧解析输入通过迁移补齐状态版本；恢复材料不会复活旧任务。其他数据组仍待对应任务实现。

## 存储分工

PostgreSQL 保存业务事实和权威关系，pgvector 保存有模型版本的检索向量。Neo4j 是可重建的关系投影，SeaweedFS 保存文件。文件地址不代替业务身份，图查询结果不直接修改正文。

## 主要数据组

| 数据组 | 建议实体 | 关键关联 |
| --- | --- | --- |
| 身份与项目 | users、external_identities、projects、project_members | 外部身份映射到内部用户，成员归属项目 |
| 规则 | policy_versions、project_policy_bindings | 任务绑定规则版本，提交时再检查当前规则 |
| 文件与材料 | storage_objects、materials、material_versions | 材料的每个版本引用不可变文件对象 |
| 解析与检索 | parse_runs、source_chunks、chunk_embeddings | 片段对应解析版本；向量对应片段与模型空间 |
| 文献与证据 | bibliography_entries、evidence_cards、notes | 书目信息、原文摘录、模型解释和作者笔记分开 |
| 稿件 | manuscripts、sections、content_blocks、block_versions、manuscript_revisions | 正文块有稳定身份，稿件版本保存块版本清单 |
| 引用与主张 | claims、citations、evidence_relations | 主张和引用绑定具体正文版本及依据版本 |
| 审阅与反馈 | review_findings、suggestions、author_decisions、feedback_items | 问题、建议、作者决定与原始反馈可追溯 |
| 执行 | jobs、job_attempts、model_calls | 每次尝试独立记录，共用业务任务身份 |
| 同步与清理 | outbox_events、projection_offsets、deletion_jobs | 跟踪图同步、撤回和物理删除进度 |
| 交付 | template_versions、export_snapshots、exports、ai_disclosures | 固定正文、题录、模板和使用说明版本 |

实体可以按实现合并，不能省略业务关系和生命周期。任务索引、状态字段不重复维护相互矛盾的事实。

## 核心约束

- 同一项目内的外键关系必须落在相同项目范围，不能仅在界面过滤。数据库采用组合唯一键或等效约束，服务端同时鉴权。
- 材料版本号在材料内唯一；正文版本只新增，不覆盖已发布的历史内容。
- 引用关联具体正文块版本和证据版本，不能只保存“第几段”或当前文献链接。
- 任务、修改提交与导出使用明确的幂等键。重复请求返回同一业务结果。
- 外部账号身份按平台及应用范围建立唯一约束，不能依赖昵称自动合并。
- 原文可定位与论点获得支持是两件事，分别记录检查结果和作者确认。

## 采纳修改的事务

1. 读取并校验建议、项目权限、当前规则和证据状态。
2. 对比客户端提交的原稿版本，冲突时返回当前版本和差异，不继续覆盖。
3. 创建正文新版本及对应引用，保存作者决定和幂等结果。
4. 更新当前版本指针，写入 outbox 事件，一起提交。

任何一步失败都不留下“正文更新、引用未更新”的状态。恢复旧稿也创建新版本，保留完整修改轨迹。

## 索引与检索

常用索引围绕项目、材料、状态、更新时间和稳定 ID 建立。任务领取使用可协调的锁与租约。列表限定字段、页大小和排序，避免一次加载全部正文。

向量保存嵌入模型、维度、处理版本与原文摘要。相似度检索限定授权项目和有效材料，必要时与关键词检索组合。模型空间变化后重建，不混存不兼容向量。

## 图关系

首版使用材料版本、证据、主张、段落版本四类主要节点，关系包括来源、提供依据、表述与依赖。每条关系带项目、业务版本和确认状态。

先从 PostgreSQL 发布已提交事件，再更新 Neo4j。事件重复时不重复建边，旧事件不得覆盖新状态。图未追平时提示同步状态，查询失败不解释成“无关联”。

## 导出与删除

导出快照固定稿件版本、题录副本、引用顺序、模板和使用说明，后台不得重新读取可变的当前稿件。

删除先冻结访问和新任务，随后按清单处理向量、图、文件和生成产物。清理失败保留状态并重试，不能为了保留历史而继续展示已撤回的敏感内容。


## 阅读结果（Issue #9）

迁移 `0013` 新增 `ReadingRecord` 与 `ReadingRevision`。一个成功任务最多发布一份模型结果，包含固定资料版本、片段、引文和来源摘要；模型无作者确认字段。作者按结果当前版本追加修订，`record + number` 唯一且版本为正数，保留修改内容、理解、核对状态、操作人和时间。项目锁内比较版本并更新指针，重复提交返回原修订；来源快照不再有效时不允许确认。原始提取与作者文字分开保存，模型读工具不返回作者修订或证据笔记。


## 原稿固定版本（Issue #10）

迁移 `0014` 新增 `Manuscript`（项目唯一）、`ContentBlock`（稳定身份）、`BlockVersion`（不可变文字/标题层级）、`ManuscriptRevision`（研究说明、操作来源、作者、请求摘要）及有序 `RevisionBlock` 清单。当前指针引用同一原稿的具体修订；未改的块复用旧块版本，恢复仅追加稿件修订并引用已有块版本。

迁移 `0015` 在数据库阻止块身份、块版本、稿件修订和修订清单被 UPDATE，校验当前指针及修订块属于同一原稿，禁止把原稿换到另一项目。外键、版本号及请求键唯一约束配合项目锁和版本比较，保障并发时只有一个写入成功。版本记录保留作者与时间，项目删除可完整级联，不在此任务增加单独物理删除历史的入口。
