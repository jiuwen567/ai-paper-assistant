# 产品需求

## 定位

面向独立完成课程论文或毕业设计论文的学生，把研究材料、文献证据、作者原稿和修改记录放在同一个项目中。重点处理依据难回查、材料与论述不一致、导师意见难落实和版本混乱的问题。

本文件记录首版范围，不表示功能已经实现。进度以 Issues 和实际验收结果为准。

## 首版范围

先支持一种中文论文类型、一个学科试点和一套院系模板。材料包括文字型 PDF、DOCX 正文、研究笔记及约定格式的实验结果 CSV。

| 模块 | 内容 |
| --- | --- |
| 项目与规则 | 账号、成员、论文要求、适用规则和辅助任务权限 |
| 材料与解析 | 双端上传、文件版本、解析、预览和原文定位 |
| 阅读与证据 | 文献卡、摘记、作者笔记、项目内检索和文献比较 |
| 研究说明与结构 | 作者记录研究问题、方法、结果；系统检查缺项并提出结构建议 |
| 原稿与诊断 | 作者编辑正文，AI 提示引用、论证及材料一致性问题 |
| 修改与反馈 | 表达建议对照、作者决定、导师意见与处理记录 |
| 关系与影响 | 查询证据路径，定位材料更正后需要复查的内容 |
| 模板与导出 | 一套模板、固定版本 Word 导出、引用及书目检查 |
| 使用记录 | 模型任务、实际采纳和作者补充的外部 AI 使用说明 |
| 后台任务 | 进度、失败重试、取消、恢复及调用成本 |
| 双端协作 | 统一身份、手机收集资料与处理待办、Web 深度编辑 |
| 数据治理 | 权限、撤回、删除及派生数据清理 |

## AI 的职责

大模型用于材料理解、跨文献比较、引用支持判断、原稿诊断和反馈拆解。对已有文字的表达建议，只在项目允许的范围内提供。

研究问题、核心论点、研究实施、结果解释和实质性写作由作者完成。阅读摘记、模型建议与正式正文分开保存，系统不提供从题目自动形成论文的路径。

## 使用边界

- 不代写论文，不编造实验、访谈、数据或参考文献，不提供规避检测服务。
- 记录学校或课程规则的来源、版本和核对状态。规则尚未核对时，保留人工编辑与确定性工具，不默认开启生成式辅助。
- 文献存在、全文可读、原文支持论断分别判断。作者接受建议不等于证明独立完成。
- 模型判断是待核对建议，使用记录不作为原创比例或学术合规证明。
- 向外部模型发送材料前明确数据范围；默认不将用户材料用于训练。

## 双端分工

Web 提供阅读、比较、原稿编辑、问题审阅和导出。小程序提供资料上传、证据阅读、短笔记、待办和局部建议处理。公众号提供入口和使用说明。

双端必须使用同一套项目数据，不能只展示静态列表。开发版联调与公开发布分别验收；账号资质、类目和授权按实际发布要求核对。

## 本期不做

不做支付会员、官方查重、AIGC 检测、多人实时协同编辑、全学科模板库和未授权全文抓取。扫描件 OCR、复杂公式与任意 Word 版式无损导入留到后续。

## 完成后的使用过程

作者导入自己的材料和原稿，整理证据，处理 AI 提示的问题；材料更正后复查相关段落，记录导师意见的落实情况，最后导出固定版本的文稿和经作者核对的使用说明。

具体任务见 [开发计划](roadmap.md)，流程见 [双端使用流程](workflows.md)。
