# 测试与验收

功能开发同步提交测试；最终验收再运行完整双端流程。下面是计划，不是已通过的测试报告。

## 样例

使用有权公开的文献、自制研究记录、作者原稿、材料更正版和反馈意见。样例附来源和使用范围，不提交真实学生论文、访谈身份或未公开研究数据。

第一组样例可包括 8 篇文献、1 份研究记录及更正版、1 份自写原稿、6 条反馈和 30 条原文锚点。规模用于启动验证，实际样本与结果如实记录。

## 必测场景

| 场景 | 通过条件 |
| --- | --- |
| 手机上传，电脑查看 | 两端材料身份和版本一致 |
| 原文回查 | 正确文件版本、位置与上下文可见 |
| 跨项目请求 | 检索、下载和任务接口均拒绝越权 |
| 重复上传或提交 | 不产生重复业务记录 |
| 手机处理旧建议 | 提示版本冲突，不覆盖新稿 |
| Worker 中断 | 任务有恢复路径，不永久停在运行中 |
| 取消或撤权 | 不再发起新调用，迟到结果不发布 |
| 资料中的恶意指令 | 不能扩展工具权限或读取其他资料 |
| 图事件重复或乱序 | 不重复建边，不恢复已撤回关系 |
| 更正材料 | 找到样例中的明确依赖，候选关联另行标注 |
| 清理部分失败 | 显示未完成并可继续，不提前宣称删除完成 |
| 导出时继续编辑 | 文档仍使用固定快照 |

每条实现任务都验证正常流程及至少一个相关失败场景。没有环境、凭据或真实调用时写明未执行，不能算作通过。

## AI 效果

分别统计阅读提取、来源支持、问题诊断和影响候选的正确项、误报、漏报。记录样本量、模型、提示词、材料版本、用时和调用成本。

与直接提问对照时，使用相同材料、任务和模型条件；无法统一的条件明确列出。比较作者核验时间、遗漏问题和返工量，不预先宣称效率提升。

数字和类型校验优先使用程序，语义判断由人工核对。结果没有依据时应提示材料缺口，而不是补编引用、实验或核心论证。

## 演示顺序

手机上传材料 → Web 回查证据 → 审阅作者原稿 → 作者修改 → 更正材料并查看影响 → 手机处理局部建议 → 展示冲突保护 → 导出 Word 和使用说明。

报告链接到实际 Issue、提交和测试记录。模型效果与软件行为分开报告，不用一个“准确率”概括全部能力。


## 阅读模型实测（Issue #9）

2026-11-05 使用本机 Ollama 0.40.14、`qwen3:4b-instruct`（Qwen3-4B-Instruct-2507、Q4_K_M），GPU 推理，上下文 16384，temperature 0，Pi SDK 1.5.0、`reading-v1`。模型文件 SHA256 为 `85e4a5b7b8ef0e48af0e8658f5aaab9c2324c76c1641493f4d1e25fce54b18b9`，来源为 [Ollama 官方模型](https://ollama.com/library/qwen3:4b-instruct)。测试未使用付费接口，token 为服务返回的实际用量，未估算硬件费用。

样例为仓库 `services/backend/core/tests/reading_samples.py` 中完全自制的虚构材料，不是真实研究，也不是效果基准。复现脚本 `evaluate_reading.py` 在 DEBUG 开发环境创建随机专用项目，通过实际上传、解析、题录、任务和 Pi 调用运行三个案例，输出 JSON，最后仅清理该项目的文件与数据。服务需自行配置，模型不随应用部署：

```bash
PYTHONPATH=services/backend uv run python services/backend/core/tests/evaluate_reading.py \
  --model qwen3:4b-instruct --base-url http://127.0.0.1:11434/v1 \
  --output .local/reading-eval.json
```

最终这一轮的结果如下。输入栏不含独立列出的缓存读取，输出包含模型重复生成的工具参数。

| 案例 | 实际效果 | 耗时 | 调用数 | 输入 / 缓存读取 / 输出 token |
| --- | --- | --- | --- | --- |
| 实验甲单篇 | 六项均保留相应原文内容，含数值、对照、重复次数及范围 | 13.94 秒 | 2 | 2957 / 2475 / 877 |
| 实验甲与乙比较 | 两篇各六项提取，条件不同判为不可比，没有换算数值后比较优劣；重复提交两次相同内容只发布一份 | 53.11 秒 | 2 | 2093 / 4930 / 4252 |
| 仅摘要 | 范围仍为摘要；全部六项被标为未提及，其中对象和定性结果属于漏提，其余缺少信息没有补编 | 4.89 秒 | 2 | 595 / 4114 / 281 |

人工核对：前两项共 18 个字段与给定材料对应；摘要应提取的 2 个字段本轮均漏提。比较结论依据可回查，但这些短自制样例不能证明真实长文阅读质量。调试中的早期运行还出现搜索循环、缺少文献、比较结构错误、重复提交及 60 秒调用超时；无有效结果的任务保留失败诊断，没有发布部分摘记。摘要曾在另一轮成功提取对象及定性结果，说明输出存在波动，不能只选成功样例报告。相同内容的重复提交现已幂等处理，但模型仍可能反复生成并耗尽预算。

本轮未做多轮统计、真实长论文、复杂单位/数值语义或不同供应商对照；#19 继续覆盖扩大样本与效果评估。软件已提供来源、数值和范围校验，内容仍默认待核对，不把“原文引文存在”当成“模型解释正确”。

## 诊断模型实测（Issue #11）

2026-11-05 沿用上述本机 Ollama、`qwen3:4b-instruct`、16384 上下文和 temperature 0，Pi SDK 1.5.0、`review-v1`。`evaluate_review.py` 使用仓库自制材料和四份短原稿，经真实上传、解析、稿件、任务及模型调用运行，最后清理专用项目。所有文字均为虚构软件验收数据。复现命令：

```bash
PYTHONPATH=services/backend uv run python services/backend/core/tests/evaluate_review.py \
  --model qwen3:4b-instruct --base-url http://127.0.0.1:11434/v1 \
  --output .local/review-eval.json
```

最终一轮实际结果如下，失败任务没有发布部分问题。输入不含另列的缓存读取，未使用付费接口，硬件费用未估算。

| 原稿案例 | 实际结果 | 耗时 | 调用数 | 输入 / 缓存读取 / 输出 token |
| --- | --- | --- | --- | --- |
| 从单一条件外推所有条件 | 模型提出了范围问题，但重复问题校验未修正，预算耗尽，无可用卡片 | 24.50 秒 | 4 | 2883 / 8162 / 1469 |
| 同一实验重复次数矛盾 | 模型识别了次数矛盾，同时把研究说明错作原稿引文；预算耗尽，无可用卡片 | 13.33 秒 | 4 | 1639 / 6979 / 992 |
| 已明确限定模拟条件的对照稿 | 发布 3 卡，均不宜确认：误读模拟性质、无视“不外推”限定、将未重复列出标准差判为矛盾 | 15.00 秒 | 3 | 2381 / 4912 / 1114 |
| 仅摘要却声称实际生产效率 | 发布 2 卡；证据缺口可确认，另一卡提示范围问题有依据，但把摘要信息不足判为矛盾过强 | 9.46 秒 | 3 | 1480 / 4879 / 656 |

逐项核对五张已发布卡：1 张可确认，1 张需要修正支持关系表述，3 张误报。三个预设有问题案例中，两个因任务失败没有交付可用诊断，属于交付层面的漏检；摘要案例的问题有定位和依据。不能把失败任务内部曾识别的问题算成已交付正确项，也不能把没有问题卡解释为原稿无误。这是实现者对自制样例的核对，不是用户作者或独立学科专家的确认。

前两轮还出现原稿与文献引文混淆、无资料时编造片段编号、参数及引文校验失败。实现据此明确字段来源、移除无资料时的读材料工具，并在现有调用预算内提供校验反馈；没有降低引文标准或自动采纳结果。此小模型在当前诊断样例上效果不合格，不能作为可靠的自动审稿判断；软件仅交付待核对建议与失败诊断。未做长稿、多轮统计、不同供应商或专家评审，后续效果评估由 #19 继续覆盖。

## 表达建议模型实测（Issue #12）

沿用 #9/#11 的本机 Ollama、`qwen3:4b-instruct`、16384 上下文、temperature 0 与 Pi 1.5.0，提示版本 `expression-v1`。三个自制原稿分别包含冗余动词、明确模拟条件与数据、缺少证据的实际应用结论。复现脚本复用诊断评测的上传、解析、原稿及任务流程，使用独立随机项目并清理：

```bash
PYTHONPATH=services/backend uv run python services/backend/core/tests/evaluate_review.py \
  --purpose expression --model qwen3:4b-instruct --base-url http://127.0.0.1:11434/v1 \
  --output .local/expression-eval.json
```

最终一轮结果如下。输入不含缓存读取，未调用付费服务。

| 案例 | 实际结果 | 耗时 | 调用数 | 输入 / 缓存读取 / 输出 token |
| --- | --- | --- | --- | --- |
| 冗余动词结构 | 返回空建议，未提供可审阅的简化表达 | 5.54 秒 | 2 | 1161 / 1038 / 73 |
| 条件、数据与否定限定 | 重复读取并耗尽四次调用预算，任务失败，没有发布建议 | 12.60 秒 | 4 | 1966 / 6910 / 944 |
| 摘要不足以支持应用结论 | 返回空建议，未把新增实验或论证写入正文 | 4.17 秒 | 3 | 1111 / 3626 / 218 |

前一轮三个任务均返回空建议；其中摘要说明曾把虚构记录称作实际研究，随后明确禁止在表达摘要中宣称研究已核实。本轮仍没有可用表达建议，不能宣称模型表达效果通过，也不能把空列表视作原稿无需改进。程序和双端测试使用受控供应商输出验证作者决定、冲突及事务行为，不作为模型效果证据。更换或配置生成模型后需重新核对内容，#19 继续评估。

真实微信开发者工具与真机未验收：用户明确尚未打开或登录开发者工具；现有自动化测试端口未连接，窗口控制工具初始化也存在 WSL 工作目录错误。微信 Bearer 接口联调与小程序组件模拟测试只覆盖各自范围，Issue #12 保持真实双端验收待办。

## AI 使用与披露验收（Issue #13）

自制稿件通过 Pi 受控供应商生成表达建议，Web 先显示两次模型调用、一条建议、零采纳；作者接受后显示一次实际采纳，并能回查原建议、决定、原稿 v1 和结果 v2。保存作者自报的外部使用后，再修改稿件或从另一窗口保存清单，旧提交返回 409，当前草稿保留；刷新后需重新核对，另有清单新版本时须明确更新保存基准。历史保留当时文本、外部使用、操作者和事实快照，审阅者不能编辑。

后端完整回归 219 项通过，随后新增一个汇总口径场景后披露模块 13 项通过。数据库用例包括重试/失败调用与未知用量、阅读核对和诊断确认不计入采纳、密钥和本地目录字段排除、并发请求唯一版本、跨项目隔离、撤权与不可改写历史。浏览器全量进程在 29 项通过后被终止，未产出结果的手机检索场景单独补跑通过；最后的清单核对状态改动重建后，桌面及手机披露场景均再次通过。具体范围见[开发说明](development.md#issue-13-实际验证)。

本清单不声称覆盖手工转抄或系统外使用，也不将生成次数、核对次数换算为原创比例。本地索引任务单列，查询向量不作为生成模型调用计数。导出留给 #17；微信待验收事项仍保持原有状态，不因 Web 披露通过而关闭。

## 导师反馈验收（Issue #14）

自制会议意见通过真实 Pi SDK 和受控供应商拆为候选，作者核对后才建待办。后端全量 237 项通过；反馈模块 17 项覆盖原始意见及来源、候选确认/拒绝、版本和规则变化、撤权、越权工具、伪造引文、空候选、并发幂等、不可变及跨项目约束。自制微信身份的 Bearer 会话能更新同一任务，Web 披露分别计数候选、确认待办和作者完成，不增加正文采纳数。

浏览器验证原始意见→候选→作者修改→导师回复：旧稿关联返回冲突且保留说明，核对最新稿后重新关联；回复固定在处理 v2，新增 v3 不继承旧确认，历史仍可回查。小程序组件模拟测试覆盖 POST、重复点击、冲突保留说明和请求键、刷新不自动改基准或位置、撤权清空、切换和返回前确认。真实微信开发者工具尚未打开或登录，小程序编译、登录及手机跨端验收未通过，Issue #14 保持此项待办。

最终一轮记录如下。输入不含缓存读取，未调用付费服务。

| 案例 | 实际结果 | 耗时 | 调用数 | 输入 / 缓存读取 / 输出 token |
| --- | --- | --- | --- | --- |
| 补充样本条件并说明指标理由 | 发布一条合并候选，未按预期拆为两项，拆分质量不合格 | 4.24 秒 | 3 | 800 / 1641 / 270 |

## 依据关系验收（Issue #15）

使用自制实验记录、作者原稿和随机测试项目，实际运行 PostgreSQL 迁移与 Neo4j 查询。后端完整回归 252 项通过；之后补充“图水位高于恢复后的业务库”的重建用例，图模块 16 项通过；最后调整删除标记查询后，删除与迟到快照场景单独复测通过。

覆盖作者核对关系与固定引文、双向路径、模型诊断候选和正文引用的区分、业务回滚不留 outbox、相同请求幂等、并发决定与并发乱序图写入、关系撤回、材料撤回与恢复后的再核对、重新解析和原稿变更、跨项目及不可变约束、撤权阻断查询。图写成功但 PostgreSQL 回执前中断后可重放，不重复建边；真实连接到不可用端口时返回 unavailable，计数为 null。投影丢失能按项目重建，较旧快照不能覆盖新投影；项目删除的清理事件可回滚、可重试，图删除标记拒绝迟到快照。

浏览器通过真实上传、Worker 解析、保存证据卡与作者关系登记，等待真实 scheduler/Worker 消费 outbox，再从正文和材料两个方向查询。能够回查固定正文、来源原话及关系历史。另一窗口先保存决定时，旧决定返回冲突且保留撤回说明；刷新、明确更新基准后可保存。撤回关系并重建后不恢复旧边。页面不可用状态使用受控响应注入验证，不显示“没有关联”；服务端断连另由真实无服务端口验证。

没有运行长时间压力或大项目性能验收；首版完整项目投影上限及事务超时见开发说明。图路径和诊断关联不构成来源真实性证明或自动支持判断。本模块没有微信端入口要求，既有真实微信验收待办不因此关闭。CI 保持轻量 PR 检查，全服务测试仍由本地或手动工作流运行。
