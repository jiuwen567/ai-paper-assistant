# Web 界面约定

Web 使用 Vue 3、[Naive UI](https://github.com/tusen-ai/naive-ui) 和 [Lucide](https://lucide.dev/guide/vue)。新页面复用这套组件，不另建按钮、表单、弹窗或导航样式。

## 工作台

进入已有项目默认打开项目总览，汇总已保存原稿字数、材料、证据卡与待处理修改，并提供研究流程入口。统计来自现有 API；部分读取失败显示错误与缺失值，不当作零。新建项目先填写项目设置与 AI 规则。左侧导航区分总览、写作、材料、审阅、反馈、依据、导出、后台任务和项目设置；手机端通过顶部导航按钮切换。

顶部快速跳转支持搜索功能、Enter 打开首项、Tab 选择与 Esc 关闭，Ctrl / ⌘ K 唤起。跳转只切换工作区，不执行模型任务或自动保存。总览每次进入重新读取；保留在其他面板中的草稿不计入总览。

材料、审阅、依据和导出使用页内标签分组。切换工作区只隐藏已挂载面板，保留尚未保存的作者草稿。离开项目、退出及覆盖草稿需要确认；切换工作区不视为保存。

原稿以正文为主，桌面显示章节目录。块类型、移动、插入与删除在编辑位置显示，手机端保持可见。研究说明、DOCX 导入和历史对照收在折叠面板中。作者仍逐块编辑和保存明确版本，模型不直接修改原稿。

## 前端工作工具

- 材料表格读取授权项目的全部材料分页，支持名称与文件名检索、分类与状态筛选、名称与大小排序、多选导出 CSV。导出仅包含筛选内选中的材料清单，不下载原件或输出正式书目；材料很多时需等待分页读取。
- 原稿提供不含空白的字符统计、阅读预览、专注写作和当前草稿 Markdown 下载。Ctrl / ⌘ S 仅在原稿工作区保存作者修改；Esc 退出专注模式。Markdown 是草稿副本，正式交付仍走固定快照 Word 导出。
- 查找替换使用字面匹配，可区分大小写；批量替换包含标题，须确认，超过单块长度限制时不执行。替换和章节追加均可撤销最近一次工具操作，后续编辑改变草稿后不再提供旧撤销，避免覆盖新文字。三种章节骨架只追加标题，不生成正文；保存仍使用现有版本与幂等校验。
- 文献矩阵展示当前阅读结果分页内的已保存摘记，可搜索、按核对状态过滤、选择比较列、回到阅读详情和导出 CSV。作者修订、模型提取、来源版本、摘要/全文范围、来源变化与原文依据分别保留，不将矩阵展示视为新一轮模型比较。未保存的阅读修订在重新打开结果、退出和离开项目时有确认保护。
- 修改看板按当前分页的已保存进度分组，支持本页搜索和定位处理记录。状态变更继续在原有处理表单中保存，不用拖动代替作者说明；作者完成与作者转录的导师回复分别展示。

本轮没有新增后端接口、业务表或浏览器本地业务存储。CSV 对引号、换行和可能的表格公式前缀作转义。

## 组件和主题

页面入口和布局位于 `src/app/`；业务组件与类型按 `src/features/<业务>/` 聚合。项目页只组合登录、列表、工作区和设置；项目表单、AI 规则、成员管理各自封装，通用异步反馈与轮询复用 `useAsyncState`、`usePolling`。基础 UI 不发起业务请求。

工作区 URL 为 `/projects/:projectId/:workspace`，标签使用 `?tab=`。刷新恢复当前位置，前进后退经过草稿保护；同项目内切换工作区保留草稿。新组件按职责拆分，运行时代码文件最多 400 行，不用压缩模板或多条语句绕过长度限制。

- `src/ui/theme.ts` 定义公共颜色、字号、尺寸与圆角，通过 `NConfigProvider` 应用；中文提示使用 `zhCN`。
- 按钮、导航、标签页、抽屉、文件上传、状态和确认框直接使用 Naive UI。图标使用 Lucide，尺寸通常为 16 或 18 px。
- `UiInput` 将现有字符串/数字模型映射到 `NInput`，保留原生 required、min/max、pattern 等校验和可访问名称。
- `UiSelect` 使用 `NSelect`，保留必填校验与 change 语义；`UiCheckbox` 使用 `NCheckbox`，支持布尔值与选择数组。这些适配层只处理表单语义，不承载业务请求或权限判断。
- `UiDisclosure` 使用 `NCollapse`，统一折叠外观。作者放弃草稿统一通过 `useConfirm` 和 `NDialogProvider` 确认。
- 控件必须显式传递 disabled，不能只依赖原生 fieldset 对自定义组件的禁用行为。标签、键盘焦点、错误提示和只读状态必须保留。

视觉采用灰白界面与墨色强调，4 px 间距基准、三级文本颜色。正文和原句/建议对照是页面重点，不加入虚构统计、装饰性看板或与任务无关的卡片。

设计审查参考 [unslop](https://github.com/heydamir/unslop)，作者 Damir Sokolovsky（[@heydamir](https://github.com/heydamir)），许可 CC BY 4.0。本项目按其间距、颜色、图标、文案、排版、布局、细节与动效检查方法调整已有业务界面；没有复制示例页面。Skill 是开发辅助，不作为应用运行依赖。

## 验证

`pnpm --filter @paper/web check` 和 `build` 检查类型与构建；`E2E_USE_COMPOSE=1 pnpm --filter @paper/web test:e2e` 通过实际导航验证桌面和手机端。浏览器场景保留真实 API、Worker、权限、版本冲突和作者确认检查，模型输出使用明确的自制夹具。

`pnpm --filter @paper/web test:frontend` 单独运行前端工作台浏览器测试，仅启动 Vite，全部业务响应使用自制接口夹具；与真实后端浏览器回归分开，不计作 API、Worker 或 Word 联调。单元测试通过 `pnpm --filter @paper/web test` 运行。

工作台原验收：类型检查、生产构建、11 项单元测试与 14 项桌面/手机前端浏览器测试通过。浏览器覆盖总览部分失败与重试、跨服务端分页材料筛选/排序/CSV、替换撤销与章节标题、保存冲突保留草稿、矩阵来源与修订、阅读草稿保护、反馈定位、空项目、只读与撤权。

2026-11-07 目录与组件重构复核：14 项工作台、6 项路由和 8 项设置组件浏览器回归通过；覆盖 URL 刷新／前进后退、草稿保护、独立表单、版本冲突、导航禁用状态与撤权返回列表。真实服务浏览器 42 个不同场景最终通过，材料空态断言修正后单独复跑；记录和环境限制见[目录与组件重构验收](verification/architecture.md)。已查看设置截图，Web 类型检查、11 项单元测试和生产构建通过。构建仍提示主包超过 500 kB。

预览只使用自制文字和专用本地账号，不把账号、密钥或真实论文放入仓库。CI 保持现有轻量检查，完整业务浏览器回归在本地运行。
