## 联调修正

- 创建项目后先进入项目 URL，再显示加载后的工作区；菜单禁用状态同时暴露 `aria-disabled`，避免刷新期间的点击被忽略。
- 创建成功提示由页面保留，表单卸载后仍可见；所有项目撤权路径统一清理选择并返回列表，保留错误提示。
- 旧浏览器测试改为验证刷新恢复当前工作区，以及覆盖草稿前取消／确认的作者决定。
- 原先超过 1,100 行的业务浏览器测试按领域拆分，复用账号与导航夹具；18 个业务用例及桌面／手机覆盖范围保留。

## 开发容器

Docker Engine 28.3.2、Compose 2.38.2 下，独立测试环境执行了 `make dev` 的初始化、镜像构建、迁移、健康检查及真实 Worker 任务往返。因本机 Ubuntu 集成服务失效，验收临时使用 Windows Docker 客户端和专用配置卷；Redis 测试端口使用 16379。正式 Compose 配置未加入这些环境绕行设置。

实际启动 Compose Watch 后，临时探针验证了前端新增／修改文件同步和浏览器 HMR，以及后端、Pi 文件同步后 API、Worker、Scheduler 的重启。探针已删除，服务恢复健康后继续运行浏览器验收。专用测试容器已停止，测试数据卷保留。

随后恢复本机 Docker Desktop 与 Ubuntu 集成，直接运行普通 `make dev`，使用正式 Compose 配置和原有本地凭据完成构建、迁移、五项依赖检查、Worker 往返及 Watch 启动。正常环境再次验证前端文件同步和浏览器 HMR。退出监听后开发容器继续运行；日常仍以 `make dev` 启动并保持监听。
