# 双端使用流程

## 1. 建立项目

作者在 Web 创建项目，填写论文类型、研究目标、截止时间和模板，登记学校或课程的辅助使用要求。小程序通过一次性绑定流程接入同一账号。

## 2. 收集材料

电脑上传文献、原稿和研究材料；手机补充聊天文件、图片和笔记。资料按用途分类，文件完成校验后进入解析任务。处理失败时说明原因，不显示为完整可用。

同一资料更新时保存新版本，区分补充、更正和撤回。不会仅因上传了新文件，就将旧证据判为错误。

## 3. 阅读与核对

作者选择资料并提出阅读问题。AI 提取研究对象、方法、结果与限制，整理为有来源的摘记或比较表。每项结果能回到具体文件版本和原文位置。

作者核对后补充自己的理解。摘记留在阅读区，不自动进入论文正文。只有摘要、材料缺项或实验条件不可比时，系统明确提示。

## 4. 作者写作

作者填写自己的研究说明，组织章节并编辑正文。系统保存稳定的正文块标识和历史版本。结构建议用于检查作者已有思路，不替作者补做研究或核心论证。

## 5. 审阅与修改

作者选择原稿范围，系统结合材料给出问题卡：哪里有问题、依据是什么、为什么需要检查、作者可以采取什么行动。

涉及实验、研究结论和关键论证的内容由作者修改。允许的表达建议以原句、建议句和差异展示，作者可接受、编辑后接受或拒绝。

提交时重新检查权限、规则、正文版本和依据状态。手机上的旧建议不能覆盖电脑上刚改好的正文。

## 6. 落实导师意见

作者录入意见并注明来源。AI 提出拆分任务，作者确认后关联章节、补充材料和实际修改。作者标记完成与导师认可分别记录，不能混为同一状态。

## 7. 材料变化后复查

先查询已经登记的证据关系，再由模型补充可能相关的位置。确定依赖和语义候选分开展示。

作者查看新旧依据、处理受影响的段落，并记录理由。有其他有效依据时提示复核，不自动删除论点或改写结论。

## 8. 检查与导出

核对未处理问题、引用、模板和 AI 使用说明。创建导出快照后，后台按固定的正文、题录和模板版本生成 Word。之后继续编辑不会改变这次交付。

## 页面安排

| 终端 | 主要入口 |
| --- | --- |
| Web | 我的论文、资料库、阅读与证据、原稿工作台、审阅与修订、检查与导出、任务中心 |
| 小程序 | 项目、收集、待办、我的 |
| 公众号 | 我的论文、收集资料、使用帮助 |

通知只作提醒，任务结果始终保存在任务中心。未订阅通知或发送失败，不影响用户查回结果。

## 演示用例
